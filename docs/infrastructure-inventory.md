# Infrastructure inventory workflow

How OpenClaw refreshes `/knowledge/inventory/services.yaml` using the `infrastructure-inventory` skill.

## Skill install

Copy [`skills/infrastructure-inventory/`](../skills/infrastructure-inventory/) to the OpenClaw skills path (commonly `/data/workspace/skills/infrastructure-inventory/`), or set `skills.load.extraDirs`.

Also install [`skills/coolify-readonly/`](../skills/coolify-readonly/) for the Coolify safety contract.

## User triggers

| Intent | Suggested phrase |
|--------|------------------|
| Full refresh | `Refresh infrastructure inventory` or `/inventory refresh` |
| Show canonical | `/inventory show` |
| Coolify dump only | `/inventory coolify` |
| Tailscale dump only | `/inventory tailscale` |
| Last diff | `/inventory diff` |

If slash commands are not generated by this OpenClaw build, use the natural-language phrases; do not invent unsupported slash-command wiring.

## Coolify-only milestone

Until Tailscale MCP is approved:

1. Query `coolify-readonly` only
2. Write `generated/coolify.yaml`
3. Build `services.yaml` with Coolify sources; Tailscale fields `unknown` / unmatched as needed
4. Apply `overrides.yaml`
5. Validate, history, atomic write, diff

## Pipeline

```text
MCP discovery
    ↓
normalized source data (generated/*.yaml)
    ↓
correlation
    ↓
manual overrides
    ↓
validate schema
    ↓
atomic write services.yaml
    ↓
diff + log
```
